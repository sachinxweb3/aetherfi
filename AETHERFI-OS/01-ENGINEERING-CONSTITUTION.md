# AETHERFI ENGINEERING CONSTITUTION

Version: 1.0

---

## Purpose

This constitution defines the engineering laws of AetherFI.

Every engineer, AI agent, automation and contributor must follow these rules.

These rules override personal preferences.

---

# Article 1 — Mission

Build a secure, scalable, production-grade AI-powered Web3 Financial Operating System.

Never optimize for speed at the cost of quality.

---

# Article 2 — Core Values

1. Integrity
2. Correctness
3. Security
4. Simplicity
5. Reliability
6. Transparency
7. Maintainability
8. User Trust

---

# Article 3 — Non-Negotiable Rules

- Never fake blockchain functionality.
- Never fake AI outputs.
- Never invent smart contract addresses.
- Never invent RPC endpoints.
- Never hide limitations.
- Never skip testing.
- Never skip security reviews.
- Never merge broken code.

---

# Article 4 — Definition of Done

A feature is complete only if:

- Requirements implemented
- Code reviewed
- Tests passed
- Build passed
- Wallet verified
- Contracts verified
- Documentation updated
- Production checklist complete

Otherwise:

STATUS = IN_PROGRESS

---

# Article 5 — Architecture First

Before coding:

- Understand existing architecture.
- Identify dependencies.
- Produce implementation plan.
- Minimize breaking changes.

---

# Article 6 — Code Standards

- Strict TypeScript
- No `any`
- SOLID principles
- Reusable components
- Small functions
- Clear naming
- No dead code
- No duplicated logic

---

# Article 7 — Security Standards

Every feature must be reviewed for:

- Authentication
- Authorization
- Input validation
- Wallet security
- Smart contract risks
- Dependency vulnerabilities

---

# Article 8 — Wallet Standards

Wallet interactions must:

- Use real providers
- Validate network
- Estimate gas
- Handle rejection
- Wait for confirmations
- Display explorer links

---

# Article 9 — Documentation

Documentation is mandatory.

Every feature requires:

- Purpose
- Architecture
- Setup
- API
- Testing
- Deployment
- Troubleshooting

---

# Article 10 — Engineering Decision Framework

Priority order:

1. Correctness
2. Security
3. Maintainability
4. Performance
5. User Experience

---

# Article 11 — Quality Gate

Before merge:

- npm run lint
- npm run build
- Tests pass
- Manual verification
- Documentation updated

---

# Article 12 — AI Engineering Rules

The AI must:

- Explain assumptions
- Report blockers
- Stop when dependencies are missing
- Never claim incomplete work is complete
- Report progress after every milestone

---

# Mandatory End Report

Always include:

- Current Milestone
- Current Status
- Progress
- Files Changed
- Tests
- Risks
- Next Task

End of Document
